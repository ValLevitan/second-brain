## Summary

The meeting settled where Claude-generated "prose" (plain-language descriptions of code) should live in each repo, and how to check it.

**Where prose is stored.** Val wanted to know the full process: put prose in the right place, write the rules so it generates when code is added, verify it works, and add a control on Andrei's dashboard to catch gaps. The team agreed prose sits next to the code, inside each repo's existing `docs/` folder, in a dedicated subfolder. Val pushed twice for a higher-level spot (or the `.claude` folder), since no human will read the full body of prose and Claude both writes and reads it. Andrei and Pavel pushed back: `docs/` is the worldwide standard and where AI looks for documentation; `.claude` is a hidden service folder for prompts, not work product. Val accepted. Result: instructions for Claude live in `.claude`, the prose (work product) lives in `docs/`, and the CLAUDE.md/README will point to the prose folder path.

**Verification.** Andrei's report will check that the prose folder exists and flag whether a pull request changed files in it. Prose is generated by Claude, but the programmer merges it into the PR and must read it. Val stressed reading works in small chunks (a paragraph per 200–400 lines of code); reading a year's worth at once is impossible for any human. Irina noted a PR must be tied to a requirement.

**Second idea (raised now, not before).** Val wants Claude to check whether closed requirements are genuinely satisfied by the prose in the repos — a match between "we closed this task" and what the prose/code actually shows. Pavel likened it to an end-to-end test. Val tied this to a cost-value view: we spend real money and hours closing requirements, so the real question isn't how many requirements a product manager writes, but whether anyone needs them and whether they earn money.

**Fable model cost (administrative).** A new, expensive Claude model ("Fable") is out — reportedly 5–10x normal cost. JVL currently spends ~$7,000/month. Andrei explained each user is capped by the token limit in their subscription regardless of model. Val disagreed that this answers the real problem: he can't tell whether the tool's higher cost buys proportionally more output. Pavel said Fable is meant to be efficient (it plans with sub-agents and delegates to Opus), but hasn't tested it. Andrei uses cheaper models for simple tasks (Haiku for email, Opus for code); Val admitted he doesn't ration. Val asked the team to keep thinking about it — no answer needed yet.

## Decisions Made

- **Prose is stored next to the code, in a subfolder under each repo's `docs/` folder** — `docs/` is the accepted standard and where AI looks for documentation. (Val, Andrei, Pavel)
- **`.claude` is for Claude's instructions only, not prose output** — it's a hidden service folder; prose is work product. (Val, Andrei, Pavel)
- **CLAUDE.md/README will point to the prose folder path.** (Pavel, Val)
- **The control report will verify the prose folder exists and check PR changes against it.** (Andrei)
- **Prose is generated by Claude but merged by the programmer, who must read it; a PR must map to a requirement.** (Val, Irina)
