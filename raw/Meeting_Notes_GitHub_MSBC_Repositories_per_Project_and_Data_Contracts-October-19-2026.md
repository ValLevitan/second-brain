## Summary

**Why now.** Val wants the three of them aligned and moving. About 45 days are left in the year. Michael is leaving, and Mery cannot work the way Michael did (his own 30-year framework and reports). Val has no time to bring someone else in, and Genadi must not spend his time on purchasing. Val believes his architecture will work for Mery. Nathan agreed.

**What a repository is.** Genadi asked to confirm the repository structure first: tags, readme files, and how a component is found (by part number, where and how it is stored). He referred to a "hardware repository standard". Val said there is no hardware repository standard, only the repository standard. Val's view:
- One repository = one project (one Jira project). Example: all monitors from all suppliers in one "Display" repository; all harnesses in one repository.
- Inside, the content is free-form: data sheets and drawings, from suppliers or made by Genadi when a supplier has none. Like code, there is no fixed table structure.
- Each repository has a readme, a Prose folder and a data contract folder. Prose and data contracts tell the AI what is needed. A GitHub Action collects everything into a release, and to Val a release is a bill of material.

**Nathan's spike.** Nathan showed his example on a branch (not merged), and shared the link in the meeting chat. Folders stand in for future repositories: sheet metal, power supply, plastics, peripherals, money devices, labels, harnesses, display. Val said this matches his table. Each folder has a contracts folder of YAML files that define the component. There is no Prose folder or ADR yet; they can be added. Each repository will also need a folder for the data sheets and other source files.

**Data contracts are generated, not hand-written.** Val asked, and Nathan confirmed: the agent (Claude) builds the data contracts from the data sheets and drawings. That is why the files are needed. Mistakes are expected. They will be caught at final assembly: if contracts do not match, the parts do not assemble, and the fix is made at the source.

**What goes in.** Only items Genadi has vetted and approved for JVL (the monitors, drawings and data sheets JVL goes with), each in the right repository: displays with displays, harnesses with harnesses, money devices with money devices, plastics with plastics. Everything he would need to build the machine by hand.

**The list.** Val: the folder list is good enough to start; repositories can be merged, renamed or deleted later. Genadi thought the table Val sent earlier was better; nobody could find it during the call. Val counted 13 repositories; Genadi said about 15. Genadi noted "hardware manufacturing" overlaps with sheet metal, plastics and harnesses; names need review.

**Who creates them.** Andrei opens the GitHub repositories. Dima (Dmitri Kovalchuk) must open the Jira projects at the same time; a project is needed before a repository.

At the end Genadi raised the parallel work on tools for Mery (continued in Segment 2).
