# RIS prose documentation standard (Jul 2 2026)

NOTES-ONLY · July 2, 2026, 10:03 AM ET · ~1h. **Attendees:** [[wiki/people/val-levitan.md|Val Levitan]], [[wiki/people/dmitri-chudinov.md|Dzmitry Chudzinau]], [[wiki/people/pavel.md|Pavel Frolov]], [[wiki/people/andrey-bosik.md|Andrei Bosik]], [[wiki/people/irina-shishko.md|Irina Shishko]], [[wiki/people/sergey-tsymanov.md|Sergey Tsimanov]].

**Purpose:** Val presented "prose" — plain-language `.md` documentation he generated that morning for the **RIS** repository (JVL's remote install-and-configure system that pushes machine settings, see [[wiki/topics/ris-remote-install-and-machine-states.md]]) using a tool called **Fable**, which scored the code-and-prose 8/10 — and proposed making AI-generated prose a company coding standard: prose lives next to the code, every pull request updates it, no one writes it by hand. This is the RIS pilot of the **code→prose** thread (continues the [[wiki/meetings/2026-04-03-val-aaron-sync-ways-multilingual-code-to-prose.md|Apr-3 code-to-prose methodology]] and the [[wiki/meetings/2026-06-30-nova-migration-and-autonomous-coding.md|Jun-30 code→prose→Capability]] demo). The morning's follow-up an hour later settled where the prose is stored: [[wiki/meetings/2026-07-02-code-prose-storage-standard.md]].

The durable substance — the prose-documentation standard (what prose docs are, how Fable generates/scores them, the many-simple-`.md`-files form, the prose-on-PR rule, and the team's duplication pushback) — lives on [[wiki/topics/ai-assisted-development.md]] (Jul-2) and [[wiki/topics/github-release-management-pipeline.md]] (Jul-2). §15.8 clear — tooling/prose-standard only; no named-person compensation.
