# Game Manifest Definition (June 3 2026)

**June 3 2026, ~10:28 AM ET (header time), ~1h 55m. Russian; summarized in English.** Attendees: [[wiki/people/val-levitan.md|Val]], [[wiki/people/dmitriy-khandov.md|Dmitriy Khandov]], [[wiki/people/irina-shishko.md|Irina Shishko]], [[wiki/people/andrey-bosik.md|Andrei Bosik]], [[wiki/people/pavel.md|Pavel Frolov]]. (Referenced, not present: Alexander Biratko, Lena Zhukova, Michael Gottlieb, Efim.) The worked example game is **Calle Ocho** (Miami's SW 8th Street), transcribed phonetically.

The opening session of a serious multi-meeting effort to demystify how a game is designed, centered on one artifact — **the manifest** — starting with Val's first requirement: a shared definition, because "manifest" means different things to different people and collides with the platform release manifest. The afternoon follow-on the same day is [[wiki/meetings/2026-06-03-white-label-experiment.md|White Label Experiment]].

Substance recorded on:
- [[wiki/topics/slot-game-design-principles.md]] — the manifest as the structure of a game scene, the reversed design→engineering direction, the ~90%-shared / per-game split, the Capability→Requirement→Features→Design Document chain replacing the GDD, and the ~80% AI reconstruction of the Calle Ocho bonus screen.
- [[wiki/topics/github-release-management-pipeline.md]] — the manifest-as-data-contract (machine-generated, never hand-written), the terminology collision with the platform release manifest, and validating the built scene against the contract by acceptance criteria with continuous parallel E2E.
