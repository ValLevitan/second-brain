# Markdown-editing tooling — VS Code vs Obsidian, don't force one tool (Oct 21 2025)

**Date:** 2025-10-21 (12:28pm) · **Attendees:** [[wiki/people/aaron.md|Aaron Bockelie]], [[wiki/people/val-levitan.md|Val Levitan]], [[wiki/people/andrey-bosik.md|Andrei Bosik]]. 17m. English.

A short tooling debate: how should JVL people edit the markdown files that must live in GitHub. Substance rolls up to [[wiki/topics/docs-as-code-and-atlassian-exit.md]]. §15.8: no compensation material.

Durable points (single source — see the topic page for the synthesis):

- **Don't force one tool; give a top-three recommendation and let people choose.** Aaron pushed back on [[wiki/people/andrey-bosik.md|Andrei]] standardising everyone on VS Code (or on Obsidian): he has "promoted Obsidian as just an accessible way to work with Markdown files, not the official way." He said it is "intellectually lazy" for staff to demand to be told which single tool to use — reply with a short set of recommendations and let them decide. He does not care how markdown gets into the repo ("Typewriter and scanned… ChatGPT could turn into markdown"). [[raw/tools_managing_markdown_files-october-21-2025.md]]
- **Obsidian can't switch remote branches; there are GitHub plugins.** Andrei's core complaint: the Obsidian git plugins show only local branches, so people must drop to the console to work with remote branches (e.g. a branch created from a Jira button). Aaron countered there are Obsidian GitHub plugins (he named **GitHub Sync** and offered to install it live); Andrei said he had already tried all the Obsidian git plugins including GitHub Sync ("He's very simple"). Aaron offered to **write a custom Obsidian plugin** himself ("in like a week") to give the missing branch management. [[raw/tools_managing_markdown_files-october-21-2025.md]]
- **The "code-first" rationale for markdown (Val).** Val restated why everyone is pushed to markdown: JVL subscribes to a **code-first** philosophy, and the only way written material can sit next to (and version with) code is a markdown file. Andrei confirmed staff understand *why* — they just want a comfortable editor (tables, images, a Word-like feel). Val's answer: they can stay in their own environment (even Word) and convert to markdown with ChatGPT. [[raw/tools_managing_markdown_files-october-21-2025.md]]
- **Val's toolbox summary (the ruling).** The tools JVL uses to manage schedules and align everyone are **Atlassian and GitHub**: **upper-level schedule management in Atlassian**, **lower-level schedule/organisation in GitHub**; documents must get into GitHub as **markdown** because the knowledge base lives next to the code; staff are **required to know GitHub basics** (as they are required to know Jira basics); JVL is **migrating away from Confluence**. "These are the tools in your toolbox if you want to work for JVL." [[raw/tools_managing_markdown_files-october-21-2025.md]]
- Aaron closed by asking whether they had considered suggesting **GitHub Desktop** as another option. [[raw/tools_managing_markdown_files-october-21-2025.md]]
- Aaron's organisational-change aside: a ~30–40-person company can afford fewer specialists than a 500–1000-person one; JVL needs people to learn the basics of git rather than have Andrei solve the tooling for them (he framed it as "organizational change management"). Val agreed he too must learn git. [[raw/tools_managing_markdown_files-october-21-2025.md]]
