Durable points (single source):

- **Jira is the only source of truth (Val's discipline push, repeated forcefully).** Val's rule: "**if it isn't written in Jira, it doesn't exist**" — every Monday he pulls each person's Jira status for the prior week, sends it to them, and they confirm right/wrong. He asked the engineers to hold a weekly **sketch/scrum** naming what they'll work on that week (or the next two) and then work to it. Weekly Monday→Monday planning cadence agreed (Monday/Tuesday meetings, since Alekseev has the most weekend progress). [[raw/Flex-Port_Smib_alignment-November-28-2025.md]]
- **Cashout "bill-return" protocol resolved — don't complete the transaction (Yavorski, HFM-255).** On a machine with a low credit cap (can't load more than ~$200), trying to add more than the machine will hold makes the bill-acceptor issue a **bill return**; the returned amount was being pushed back to FlexPay as cash, but a returned amount that mixed **player/redeemable credit and cash** converted incorrectly. Options weighed: a **new FlexPay command** or an **extra field** on the cashout command (Yavorski leaned to a new command to protect backward compatibility). **Resolution with Pavel:** the more reliable path is to run the cashout as a **two-phase command and NOT complete phase 2** when the machine rejects the bill — avoiding a new command/field and the risk of a hang if power/connection drops mid-transaction. Yavorski to rework it from a cash-return to "phase-2-not-completed" and test in real conditions. [[raw/Flex-Port_Smib_alignment-November-28-2025.md]]
- **Negative-scenario work is on the FlexPay side (Dima Chudinov).** Task **TF-256** (negative cashout scenarios) needs work from **[[wiki/people/dmitri-chudinov.md|Dima Chudinov]]** (FlexPay); not scheduled this week — ~1.5 weeks out (not before ~the 10th). [[raw/Flex-Port_Smib_alignment-November-28-2025.md]]
- **New validator-diagnostics feature (CPI-477, on Dima Chudinov).** Alekseev flagged there is **no diagnostics for the bill-validator / cash-box state** — with the cash box removed or the validator disconnected, nothing is reported and the system keeps running, costing ~2–3 weeks of confusion. Pavel created **CPI-477** on Dima Chudinov: a feature to analyse the bill-acceptor state (e.g. missing cash box, or not connected) and produce an appropriate report. [[raw/Flex-Port_Smib_alignment-November-28-2025.md]]
- **The "eco" test-machine problem, and Val's objection to it (ICF-258, on hold).** Alekseev has **two small "eco" gaming machines** at home (used because there's no room for full machines — they fit in a garage); **one never worked** (wants a progressive installed) while the identical other one does. Val's durable point: these machines are deliberately built with **hardware/BIOS anti-tamper "traps"** so software written for a one-screen machine can't run a two-screen setup and machines can't be assembled from market-bought parts — so cobbling the eco machines into a test rig is fighting JVL's own design and is "the wrong approach." Task ICF-258 stays on hold; Val questioned why two people were on the Linux-variant task. [[raw/Flex-Port_Smib_alignment-November-28-2025.md]]
- **Rockchip Linux image / device-tree work (Alekseev, HFM-304 → ICM-327).** Alekseev found **5 usable Linux image sources** (Ubuntu, Debian, Buildroot) that boot from SD card **with sources**, but they work only with **one screen** and need config for **two screens + touchscreen**. Pavel pointed him at Aaron's AI-generated build system (builds Linux + root filesystem via Buildroot with a correct device tree, on Linux 6.1 for the "blue" board, with Aaron's networking fix and confirmed two-screen support). Touch-over-USB works across all images but currently spans both screens (a top-left touch on screen 2 registers on screen 1) — Pavel says easily configured; Genadi noted the I2C touch on these boards is purpose-built for the touchscreen. Pavel added acceptance criteria to **ICM-327** (device-tree config): an **LVDS monitor with touchscreen**. See the ARM/Rockchip decision (Nov-28). [[raw/Flex-Port_Smib_alignment-November-28-2025.md]]
- **Aaron won't finish; take his work back and get his sources.** Both Pavel and Val: Aaron "does it while it interests him, never finishes." Plan — **close Aaron's genuinely-done tasks, tell him nothing more is needed, and get the image/sources from him**; redistribute the rest between Pavel and Alekseev. Aaron's valued contribution: the **device-tree ("device three") work + Ethernet fix** for this specific Linux on this specific board — not available ready-made anywhere (Alekseev partly disagreed: "it's all standard, documented" — but conceded he'll have to dig into the device tree regardless). Val to open a meeting with Aaron so Pavel can walk his tasks and demand "done? give us the source." [[raw/Flex-Port_Smib_alignment-November-28-2025.md]]
