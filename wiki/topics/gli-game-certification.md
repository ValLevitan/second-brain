# GLI game certification

How JVL gets its games approved for the floor, and why that process is a strategic constraint.

## The core problem

Every game must be tested and approved by [[wiki/organizations/gli.md]] (Gaming Laboratories International), and JVL must hold the license, before a game can ship and be placed on a floor. As JVL scales up game production, GLI approval becomes a **bottleneck**: it is slow and priced by testing time (~$170/hour), so a fast-producing studio can still be gated by certification [[raw/gli_visit-jan-7-2025.md]].

## Layered standards

Approval is layered: a base standard such as **GLI 11**, plus additional per-jurisdiction requirements (e.g. Georgia vs. Arkansas). A game already approved to one standard may transfer to another jurisdiction at a lower "transfer cost," which JVL could pass on to the client [[raw/gli_visit-jan-7-2025.md]].

## The automation idea

Val wants to reduce the most expensive, most labor-intensive block of GLI testing — the **math** verification (identified by GLI's Dan as the costliest) — by submitting data in whatever format GLI's tools can ingest automatically, or by building/certifying a shared virtual testing tool. As of this discussion JVL could not get a clear answer from GLI on which forms of automation GLI would accept [[raw/gli_visit-jan-7-2025.md]].

*Inference: this is an early, exploratory conversation, not a settled process — Val is trying to map GLI's cost structure so it can be attacked. Flagged as inference.*
