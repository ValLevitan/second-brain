# Wi-Fi goes onto the Flex-Port board; the external router stays

The opening and longest thread of the [[wiki/meetings/2026-09-07-wifi-on-flex-port-and-qr-provisioning.md|Sept 7 2026 9:08 AM call]] (Russian). [[wiki/people/val-levitan.md|Val]]'s question was whether a reliable wireless link is possible so JVL does not have to pull cable at every location; [[wiki/people/evgeniy-alekseev.md|Evgeniy Alekseev]] answered immediately — "Конечно, есть вай фай" — and set out the options [[raw/Meeting_Transcript_WiFi_Module_on_FlexPorts_and_Provisioning-September-7-2026.md]].

**This reverses, for the full-size Flex-Port, the position taken two weeks earlier.** On Aug 24 2026 Val had ruled Wi-Fi out for the Flex-Port-Mini — "Вай фай не пройдёт" — on [[wiki/decisions/2026-08-24-flex-port-mini-via-second-sas-only.md]], over Genadi's antenna-per-machine-model objection and Pavel's objection that a central point must see every machine directly. Both objections are taken up and answered here. Treated as **evolution, not contradiction**: the earlier ruling was about the Mini inside a metal cabinet, this one is about the full Flex-Port whose front protrudes through a plastic bezel, and the intervening two weeks produced a module, a topology and a certification answer.

**This is a LOCAL-link decision, not a backhaul decision.** The Wi-Fi carries Flex-Port ↔ router ↔ Flex-IQ/Flex-Pay inside the premises. The site's uplink is still the cell modem — Val, arguing that connection telemetry can now be sent home, said "сейчас у нас уже стоит, у нас будет [LTE] модем" *(transcript "элфимодом")* [[raw/Meeting_Transcript_WiFi_Module_on_FlexPorts_and_Provisioning-September-7-2026.md]]. So this does **not** displace [[wiki/decisions/2026-09-04-north-america-modem-variant-and-ask-kore-for-the-apn.md]] or [[wiki/decisions/2026-08-21-cell-modem-on-every-machine-from-september-1.md]] — the two layers are complementary, and nothing in either Sept-7 source proposes Wi-Fi as an answer to the "7455" LTE failure.

## The jamming objection, raised and dismissed

[[wiki/people/pavel.md|Pavel Frolov]] put Val's worry into words: "вайфай легко зафлудить… если ктото злоумышленник придётся своим недорогим устройством, которое… перегружает все каналы вайфай[,] то у нас вся сеть сразу же ложится" — a cheap jammer saturates the channels and the whole network drops. [[wiki/people/andrey-bosik.md|Andrei Bosik]] confirmed such devices exist — "китайские есть, которые создают сумасшедшую интерференцию… забивают вот этот канал там 2 и 4 герца полностью по всем частотам" (the 2.4 GHz band) — but argued the attacker must physically enter the premises: "человек должен попасть внутрь помещения… он же ж не будет с улицы стоя[ ]это производить такую манипуляцию," adding "а кто это будет делать? Зачем кому это вообще делать?" Val accepted it with a fallback: "если уже появился такой лакейшин, ну хорошо, тогда мы кладём провода" — if a location gets jammed, they cable that location. (Bosik assumed camera coverage would identify the culprit; Val corrected him — "там нету видеонаблюдения. Мы говорим про локе, которые не казино.") [[raw/Meeting_Transcript_WiFi_Module_on_FlexPorts_and_Provisioning-September-7-2026.md]]

## What was decided

- **A module soldered onto the Flex-Port board, not an external module.** Alekseev: "Либо этот модуль вставить в в плату [Flex-Port]. Это будет намного дешевле и проще. Вот то есть там стоимость может будет 4 $5 за борт" — **roughly $4–5 per board**. Pavel checked the FCC position; [[wiki/people/genadi-peari.md|Genadi Peari]] answered that it is already covered: "Он уже он уже включен." Genadi compared it to the module already on the Rockchip board — "Такой же, как у тебя стоит на рокчипе, например. Похожий." A PCI-attached variant was raised by Bosik and dropped as too complex (Pavel: "нам не надо, это сложно слишком уже[,] вот это проще будет") [[raw/Meeting_Transcript_WiFi_Module_on_FlexPorts_and_Provisioning-September-7-2026.md]].
  - *Cost note, not reconciled:* on Aug 24 2026 Genadi had put the added cost of a Wi-Fi module on a port board at "$10 будет в любом случае" [[raw/Meeting_Transcript_Flex_Port_Mini_Capabilities_Design-August-24-2026.md]]; Alekseev's Sept-7 figure is $4–5. Different device (Mini vs full Flex-Port), different speaker, two weeks apart, and neither call mentions the other. Both recorded as spoken.
- **The module's standard firmware, not JVL firmware.** Alekseev's two paths: standard firmware where "чтоб нам ничего не писать вообще" — it runs over a command protocol he named as "IT commond" *(garble; the derived notes read it as **AT commands** [[raw/Meeting_Notes_WiFi_Module_on_FlexPorts_and_Provisioning-September-7-2026.md]])* on a UART, so the existing WebSocket channel is simply duplicated: "мы можем, грубо говоря, просто раздвоить… соединения[:] одно проводное[,] одно вайфай. Сети может даже клод справиться, наверное… это чисто скопировать 2 такой же канал по веб соке." He called it "самое простое логичное решение" [[raw/Meeting_Transcript_WiFi_Module_on_FlexPorts_and_Provisioning-September-7-2026.md]].
- **Mesh networking rejected.** The alternative path was JVL's own mesh firmware plus a server on the access point — the transcript renders the server type as "антикетит сервер" and the derived notes read it as an MQTT-style server *(garble flagged; no product name is asserted here)* — because mesh "не поддерживает передачу… протокола[ ]веб soket" and "это займет больше времени." Val: "я пока не вижу нужды для нас писать [mesh], я понимаю превосходство mash[,] я понимаю[,] это очень удобно в теории. Но в основном это нужно для большего размера лакейщина." Fallback is ordinary reach extension — Val: "Экстендер и амплифайеры можно доставить" — and Alekseev noted modern extenders carry mesh support anyway: "сейчас эти экстенд[ер]ы, они… с поддержкой мэш нетворк в основном" [[raw/Meeting_Transcript_WiFi_Module_on_FlexPorts_and_Provisioning-September-7-2026.md]].
- **An external commercial router stays the access point — Val withdrew his own cost-saving idea.** Bosik asked the question and stated his preference for the opposite: "мы хотим использовать роутер или мы точкой доступа тоже хотим сделать какойто из наших девайсов?… мне 2 вариант, лично больше нравится." Pavel supported it on the hardware fact that "этот модуль уже стоит у нас на р к 35 68" — the **RK3568** in Flex-IQ and Flex-Pay already carries the module. Val agreed at first — "давайте поднимать это у себя[,] нам не нужно тратить деньги на раутер" — then withdrew it himself: "мы не будем исключать[ся], я дурную идею дал… Я просто… потупому сказал[,] без мозгов." The engineering case against it: Alekseev — "айкью… он имеет там свой чип[,] то у него нет антенн[,] там 2 трёх антенн[,] он очень слабый" and doing without a router means "либо самому писать[ ]фактически роутер"; Genadi, flatly — "Андрей[,] это не экономия, это надежно здесь. Ротор поставить[,] этого не ставить[,] это не экономия" [[raw/Meeting_Transcript_WiFi_Module_on_FlexPorts_and_Provisioning-September-7-2026.md]].
- **Topology, settled by [[wiki/people/andrei-klimovich.md|Andrei Klimovich]]:** "роутер может стоять гдето условно в игровой зоне под потолком[,] какимнибудь безопасностью… IQ с ним общается по вайфаю[,] и все порты общаются тоже по вайфаю" — router hidden in the gaming area near the ceiling, Flex-IQ and every Flex-Port talking to it over Wi-Fi. Val added it should be hidden ("спрятанная"). Klimovich also asked whether there is a cap on how many machines can attach; Bosik: because the router is a third-party device, "там ограничения это только сам роутер" — the router's own limit and nothing else [[raw/Meeting_Transcript_WiFi_Module_on_FlexPorts_and_Provisioning-September-7-2026.md]].
- **Wired stays supported and must be tested.** Val: "вай фай вай фай всё хорошо, но провода остаются проводами. У нас есть куда подключить, мы можем это провести, мы[ ]это проверяем, это должно работать." Bosik: "Однозначно" [[raw/Meeting_Transcript_WiFi_Module_on_FlexPorts_and_Provisioning-September-7-2026.md]].
- **Router brands must be American or allied-country.** Val: "нам нужно американские роутеры, потому что китайские будут… запрещены в Америке через некоторое время." Bosik offered Cisco — "остается американская[,] только циска наверно" — and confirmed the sub-brand relationship when Val groped for the name: "Линксис это и есть циска[,] это суббренд циска," positioned at home/small-office against Cisco's mid- and large-business segment, at roughly half the price (Val: "они дешевле… в 2 раза"). **Nokia** passed (Alekseev runs one at home and asked "это чей[?] не китайский?"; Bosik answered "Финны" twice, while Val and Pavel both said Swedish — Val: "Nokia шведский[,] это пойдёт" — the nationality is inconsistent in the source, the acceptance is not). **MikroTik** passed as EU — Pavel: "микротик это что же Евросоюз?" Bosik: "Литва." Val: "Это пойдет." Bosik had also named "зюксели" (ZyXEL) in passing, with no ruling on it [[raw/Meeting_Transcript_WiFi_Module_on_FlexPorts_and_Provisioning-September-7-2026.md]].
- **Flex-Port drops to one serial connector, freeing board space and a UART.** Space was the live constraint — Alekseev: "места всё меньше и меньше на этой [плате]"; Genadi's first suggestion was to drop a flash bank ("Выкинь 2 банк[.] Флэш"), then Alekseev asked "нам нужно обязательно 2 коннектора?" and Genadi answered "Выглядит, что нам один нужен," Pavel concurring. Alekseev: "если я 2 убираю, то там как раз будет и место, и [UART] для соединения." Genadi added that the printer UART is spare in this variant — Pavel: "Поскольку нам принтер не нужен в этом варианте, мы просто можем сейчас сюда втыкать" — and that he had already sent the SAS arrangement: "мы уже договорились[,] куда сас[,] я уже… послал уже." Genadi's summary: "нам 3 сериальных порта не нужно… на порте, то есть один можно убрать… [остаётся] 2[ ]для для вай фая" [[raw/Meeting_Transcript_WiFi_Module_on_FlexPorts_and_Provisioning-September-7-2026.md]].

## The antenna, the one thing left unresolved

Alekseev wanted a module with its own onboard antenna — "модули есть либо [со] собственной антенной[,] либо с внешн[ей], но я думаю, нам надо применять со своей антенной" — citing four devices he has built that way, one of them inside a fully closed metal box: "одно из устройств, которое разрабатывал… это зарядное устройство, и этот модуль со своим [antenna] вообще стоит внутри железного[,] полностью закрытого ящика" [[raw/Meeting_Transcript_WiFi_Module_on_FlexPorts_and_Provisioning-September-7-2026.md]].

Val refused, from experience: "Друзья[,] со своей антенной не пойдет, это никогда не работает. Я уже натыкался на эти грабли, я на них наступал каждый раз… потому что меня какойто инженер [уверял], что это работает? Это никогда не работает." Pavel backed him on the enclosure — "у нас… железный огромный корпус и чуть чуть пластмаска, которая торчит… я очень сомневаюсь, что она нормально будет проводить." Genadi pointed at the geometry that makes it solvable: "у нас [порт] торчит наружу, и там огромный периметр[,] по всему периметру можно пустить [антенну]"; Val: "У нас огромный пластиковый базл" [[raw/Meeting_Transcript_WiFi_Module_on_FlexPorts_and_Provisioning-September-7-2026.md]].

**Alekseev's constraint is regulatory, not physical, and it is the ruling:** "мы не можем сделать там какуюто свою антенну. Мы должны применять сертифицированную антенну, если мы хотим сертифика[цию]… все модули сертифицируются с определёнными видами антенн." And the choice is one-way once soldered: "если мы уже припа[ива]ем модуль со своей [внутренней антенной,] мы уже не подключим [внешнюю]." Genadi asked for the socket to be fitted regardless — "опционально можно поставить со[кет]… для сертифицированной антенны" — and Alekseev went as far as "теоретически, как мне помнится, у них одинаковый [pinout], поэтому можно [паять] либо тот[, либо другой]… либо оба," without committing. A protruding router-style antenna was ruled out by Genadi and Val together ("Мы не можем этого" / "Не можем") [[raw/Meeting_Transcript_WiFi_Module_on_FlexPorts_and_Provisioning-September-7-2026.md]].

One radio question was closed: Pavel — "вся передняя панель… закрывается пластмассовым корпусом… в эту сторону у нас… нет проблем с радиосигна[лом]"; Genadi — "Абсолютно[,] это все чисто" [[raw/Meeting_Transcript_WiFi_Module_on_FlexPorts_and_Provisioning-September-7-2026.md]].

## Timing

Genadi wanted the module in the board revision now under way, before the large order goes out: "вы сейчас делаете… изменение этого порта[,] и перед заказом вот этого большого количества… вставляете туда вайфай модуль." Alekseev agreed ("Да могу"). On software he put the standard-firmware route at "пару недель[.] Максимум," noted "у нас же бортов нету" — no boards yet — and offered a temporary mock-up in the meantime ("какоето временный макет сделать"). Val, asked how long, had already answered himself: "Мне нужно это завтра," and rejected the mock-up as the deliverable — "завтра готовый продукт[,] макет нам не нужен" [[raw/Meeting_Transcript_WiFi_Module_on_FlexPorts_and_Provisioning-September-7-2026.md]].

At the [[wiki/meetings/2026-09-26-flex-port-telnet-console-and-gui-harness.md|Sept-26 Flex-Port development sync]] (Russian), [[wiki/people/pavel.md|Pavel Frolov]] said the "порт 9" branch holds "какая то часть работ по вайфай модулю е с п 32 c 6" — the module is an **ESP32-C6** — and that pull requests "порт, 51 и порт 68" will be committed into it. Who wrote the Wi-Fi part is not stated. [[raw/Meeting_Transcript_FlexPort_Telnet_Console_and_GUI_Harness-September-26-2026.md]]

- **Firmware.** "этот модуль прошит. Прошивка эти команс" — read as AT commands (inference), which matches the Sept-7 notes' reading of Alekseev's "IT commond". [[raw/Meeting_Transcript_FlexPort_Telnet_Console_and_GUI_Harness-September-26-2026.md]]
- **WebSocket.** Alekseev asked if they had tried WebSocket. Pavel: "Я в вебсоке встроенный в эту прошивку не пробовал"; WebSocket is used "на st m 32". The code is now unified for Ethernet and Wi-Fi — packets are built the same way, but over Wi-Fi "Идут свои команды" while Ethernet goes direct. Alekseev began to ask whether Wi-Fi should be built into the WebSocket, then: "Ну ладно это потом." [[raw/Meeting_Transcript_FlexPort_Telnet_Console_and_GUI_Harness-September-26-2026.md]]
