# The naming convention was inadequate, and the fix has to be written down

The opening block of the [[wiki/meetings/2026-09-04-naming-convention-standards-and-nova-conversion.md|Sept 4 2026 afternoon game-development meeting]], and the sharpest argument in it.

## The root cause

[[wiki/people/lena.md|Lena Zhukova]] described the mysterious asset mismatches the team had spent two weeks chasing: **Fire Island games were built first as single games, so many assets share the same names** with nothing saying which game they belong to — "there are a lot of same names, like… Transition, for example, or **big green talker**. It's not specified that it's **Larosa** big green talker or **Crescent City Karnava** big green talker." — i.e. **La Rosa** and **Crescent City Carnival**, two Fiery Ice Link titles [[raw/Meeting_Transcript_Naming_Convention_Standards_and_Nova_Conversion-September-4-2026.md]].

Val named it immediately as a naming-convention problem — "it's a… issue with the naming convention standards, right? Or, or the lack, the lack of standards for naming convention" — and Lena resisted the framing, arguing the product had changed and assets were being reused from single-game products for the link product. The group settled it between them [[raw/Meeting_Transcript_Naming_Convention_Standards_and_Nova_Conversion-September-4-2026.md]]:

- **[[wiki/people/efim-podvoiski.md|Efim Podvoiski]]'s formulation, the one that stuck:** "Convention was there, but it was inadequate."
- **[[wiki/people/michael-gottlieb.md|Michael Gottlieb]] agreed and located it:** "the naming convention was adequate and acceptable if it was just a single game release. Where we ran into trouble is we have multiple games in the umbrella and the naming conventions were not set up for that."
- **The fix that was actually made:** "Now each like folder and each like export should contain like… **unique game code names**. That's it. It's only one simple decision" (Lena).

## "Finally, we have a verbal agreement"

Val asked whether the new standard was documented. Lena: "**No, it wasn't [documented]. It was verbal agreement.**" Val: "Amazing! Now we have a verbal agreement. Finally, we have a verbal agreement. I cannot help myself but you just to be sarcastic." [[raw/Meeting_Transcript_Naming_Convention_Standards_and_Nova_Conversion-September-4-2026.md]]

The disagreement that followed is worth keeping because both sides are on the record:

- **Michael:** "This just happened within the last couple of days." And, with feeling: "**This has been the worst ******* development process I've ever had at JVL for one game release. It has been an absolute mess.**" [[raw/Meeting_Transcript_Naming_Convention_Standards_and_Nova_Conversion-September-4-2026.md]]
- **Val's counter on the history:** "**The standards are always agreed verbally. It becomes tribal knowledge. It carries through the company. And I have been trying to root it out for years.**" [[raw/Meeting_Transcript_Naming_Convention_Standards_and_Nova_Conversion-September-4-2026.md]]
- **Michael, respectfully disagreeing:** "I have developed, we have developed **well more than a dozen games** prior to this point without this problem." Val's answer was that this is exactly the point — "**yes, because you kept your word. You all agreed, and you kept that word**… And you kept that concept verbally, everybody knew it, and it was verbally kept" — and the challenge that followed it: "**point me to a repository that lists the standards… If the repository doesn't exist, then it will be impossible to keep standards in the long time, in the long run.**" Michael: "Agreed." [[raw/Meeting_Transcript_Naming_Convention_Standards_and_Nova_Conversion-September-4-2026.md]]
- **Val then gave up on the argument, in terms.** "It seems like there is absolutely zero chance. I stand 0 chance of proving my point… so I have a choice, either waste this meeting on an argument or just give up and continue with the meeting. So I choose to continue with the meeting. 100% disagreed with you. Ridiculous statements. Bunch of silly, childish, ridiculous statements. Totally not professional… I choose not to continue. Let's move on." He came back to the same point calmly ten minutes later — "these agreements, they don't hold. People change, people forget" — and again in his closing statement ([[wiki/decisions/2026-09-04-point-claude-at-the-standards-repository-first.md]]) [[raw/Meeting_Transcript_Naming_Convention_Standards_and_Nova_Conversion-September-4-2026.md]].

## What was decided

- **Assets are not renamed.** Lena warned that renaming now would cause bigger problems, since branches for some games are cut from already-finished games and the names already exist. Michael cut it off: "**There's no reason to rename assets. This was a folder structure problem. We have addressed the folder structure.**" Val's counter stands beside it: "the folder structure problem will continue until we develop standards" [[raw/Meeting_Transcript_Naming_Convention_Standards_and_Nova_Conversion-September-4-2026.md]].
- **The asset folder structure and the multi-game naming convention get documented.** Michael: "We need to document what it is that Lena is articulating. So yes, let's please document what the folder structure should look like." His first suggestion was "one confluence page that says… default folder structure with the name of the folder"; Val challenged the venue — "Why does it have to be a confluence page?" — Michael: "It doesn't have to be… It can be anything you want it to be. All it needs to be is an articulation of what the asset folder structure is." The venue was settled in Val's closing statement: the GitHub Knowledge Base repository, Standards folder [[raw/Meeting_Transcript_Naming_Convention_Standards_and_Nova_Conversion-September-4-2026.md]].
- **Documents already exist for Omni/NOVA but not for Rage Studio.** Lena: "we have this document for Omnia, for Nova, when we started to develop games in Omnia, like **Fortune Football** or **Ca[lle Ocho] Omnia**, but we don't have this document for… **Rage Studio**" — and, with a shortage of artists and a release to finish, she asked to start after next week's release. Val questioned why the convention should differ at all between Nova and Rage Studio; Lena's reason was different asset types and a different storage structure. Val: "We can still keep everything in GitHub. Nothing's stopping us. Even in Rage Studio, we could still have standards in GitHub." Lena clarified she was talking about asset structure; Val, about naming-convention standards [[raw/Meeting_Transcript_Naming_Convention_Standards_and_Nova_Conversion-September-4-2026.md]]. *(The transcript renders Calle Ocho as "Caiochi Omnia" — a garble per §4.)*
- **Branch-selection rule, as near as the meeting got to one: take the branch closest to the current requirements of the product being developed.** Lena stated it, Efim agreed ("Yes"). Val said twice that he still did not fully understand the decision method, so this is a working rule, not a settled standard [[raw/Meeting_Transcript_Naming_Convention_Standards_and_Nova_Conversion-September-4-2026.md]].

## The second root cause: which branch to start from

This one was never resolved. Val wanted the methodology and the owner — "I would like to understand how to properly make a decision in the future from which branch to start… what methodology to use for making that decision, or what information, or how to make that decision, or where to find it." Michael's answer — "That information will be in JIRA going forward, and I will specify [it]" — Val rejected twice: "**This is not helpful. Not helpful. Michael, this is not helpful.**" [[raw/Meeting_Transcript_Naming_Convention_Standards_and_Nova_Conversion-September-4-2026.md]]

- **What went wrong concretely (Michael's account).** "We finished Jackpot Rush **at any bet** for Georgia"; then on Georgia V3 "I'm looking at Jackpot Rush and it says **with max bet**. So the only theory I can come up with is they grab the Florida non at any bet graphical asset and put it in there." He added JVL had literally named the product "AAB" for *at any bet*. Lena's version: "they decided to cut a branch from already existed product and they cut it from… wrong product[s]. They did not ask me… **Irina decided with somebody else that we are going to cut it from Florida branch**." Her later guess at the reason: "**Florida product was tested and Georgia was just like all assets were inserted, but it was never tested because we cancelled it at some point**" [[raw/Meeting_Transcript_Naming_Convention_Standards_and_Nova_Conversion-September-4-2026.md]].
- **Who should be consulted.** Lena: "Rather with Michael… and Juan, then with me, because… [Juan] is creating requirements for the product, because [Juan] is **VP product owner**, VP product owner is creating backlog for the product and requirements for the product." Juan disagreed about himself: "I don't even know where these file repositories are… so I have no idea of the naming convention." Michael: "in theory, they should not have had to ask us the question, because we had a finished jackpot rush for Georgia" [[raw/Meeting_Transcript_Naming_Convention_Standards_and_Nova_Conversion-September-4-2026.md]].
- **Val refused the blame framing.** "I actually don't really care what, who is at fault. **My goal is to determine that it never happens again.**" And: "I don't see simply mature people grabbing just in an abstract… There has to be something else which I'm trying to understand what it is" [[raw/Meeting_Transcript_Naming_Convention_Standards_and_Nova_Conversion-September-4-2026.md]].
- **What a branch is, explained to Juan by Efim** (Juan asked outright: "for my sake, what is a branch? Is it a structured Windows folder…?"). Efim: branches live in the source-control tool so that "changes that made for other products or for improvement… don't contaminate the current development"; because JVL has different products going different ways and sometimes returns to a product or moves it to another jurisdiction, "you have to make a decision from what… snapshot… you start your product, and… that's the branch." And why it is hard: "you have similar product, but very old code base with old bugs and no features in data center… and you have newer products, but different games and what to choose. It's not always very clear where to start" [[raw/Meeting_Transcript_Naming_Convention_Standards_and_Nova_Conversion-September-4-2026.md]].
- **The other bugs, for completeness.** Audio bugs from two separate causes: "there were some instances where **Vladimir** had provided the wrong audio file… There were other instances where the programmers made a mistake" — specifically "an issue where **Anton** used the wrong sound file" and "**Rodeo Queen** had music from **La Rosa**." Michael attributed the wrong-file class to the same multi-game confusion, not to naming: "But it can't be a naming convention" [[raw/Meeting_Transcript_Naming_Convention_Standards_and_Nova_Conversion-September-4-2026.md]]. *(Neither "Vladimir" nor "Anton" is surnamed here and neither is resolved to a page — §4.)*
