# NOVA remote update: NOVA only, Texas first, full architecture before the MVP split

At the [[wiki/meetings/2026-10-30-nova-remote-game-update-architecture.md|Oct-30 9:03 AM meeting]] (Russian; Val, Pavel, Chudinov, Biratka, Irina) the team talked through how games and other software reach a NOVA machine remotely. Val asked for a technical brief for the engineers that can grow into the architecture of the whole product [[raw/Meeting_Transcript_NOVA_Remote_Game_Update_Architecture-October-30-2026.md]].

## What was decided

- **NOVA only.** Chudinov asked whether this covers the current platform too. Biratka: "только нова"; Irina: the future, "Потому что все, что мы рассказали в текущем не работает"; Pavel: "Да для нова" [[raw/Meeting_Transcript_NOVA_Remote_Game_Update_Architecture-October-30-2026.md]] [[raw/Meeting_Notes_NOVA_Remote_Game_Update_Architecture-October-30-2026.md]].
- **Texas first.** Chudinov asked if the first market is Georgia. Val: "Техас Техас". Irina: in Texas no certificates are needed — "свободные руки в плане обновлений" [[raw/Meeting_Transcript_NOVA_Remote_Game_Update_Architecture-October-30-2026.md]].
- **Full architecture first, MVPs after.** Pavel asked for something the team could check within two weeks. Val: no schedule and no MVP 1/2 split yet — "Давайте составим общее как бы архитектуру, как это работает, а потом разобьём уже на что можем сделать и за какой срок." Later: the machine can be released now and these parts added MVP by MVP, but the final picture ("например, MVP 10") must be agreed now [[raw/Meeting_Transcript_NOVA_Remote_Game_Update_Architecture-October-30-2026.md]] [[raw/Meeting_Notes_NOVA_Remote_Game_Update_Architecture-October-30-2026.md]].
- **One list of allowed updates.** Pavel: for other operators who own JVL machines, JVL must prepare and check each package; for its own machines there may be many more updates. Val: the list of what may be installed "в принципе должен существовать одинаково" for JVL's machines and others'; even if the lists differ, the list must exist in both places. A buyer "может пользоваться нашим менеджмент платформой" [[raw/Meeting_Transcript_NOVA_Remote_Game_Update_Architecture-October-30-2026.md]] [[raw/Meeting_Notes_NOVA_Remote_Game_Update_Architecture-October-30-2026.md]].
- **An admin dashboard and the infrastructure behind it.** Val: an admin dashboard must say what may or may not go on each machine; sold machines must leave with JVL's administration; "мы должны создать эту инфраструктуру" [[raw/Meeting_Transcript_NOVA_Remote_Game_Update_Architecture-October-30-2026.md]]. Pavel: it looks much like what Chudinov built for Transactional — the whole fleet of terminals, with chosen ones picked for update [[raw/Meeting_Transcript_NOVA_Remote_Game_Update_Architecture-October-30-2026.md]].
- **Where decisions are written.** Pavel: remote update is not a separate GitHub project — its parts live in the Linux repositories for x86 and for the RK board, in a Galaxy repository (Chudinov: "Наверняка" a separate one) and in the LGS project. The architecture decisions (ADRs) go in the NOVA integration repository, because it crosses all repositories. Val: "Договорились" [[raw/Meeting_Transcript_NOVA_Remote_Game_Update_Architecture-October-30-2026.md]] [[raw/Meeting_Notes_NOVA_Remote_Game_Update_Architecture-October-30-2026.md]].
- **Scope of the documents.** Pavel: the update architecture is written from this meeting; Galaxy was only touched — it controls updates through an update manager and a module that links component versions; NOVA as its own project covers the engine, games and framework [[raw/Meeting_Transcript_NOVA_Remote_Game_Update_Architecture-October-30-2026.md]].

## The update model talked through

Not settled in detail; Pavel: "решение писать нет. Потому что решений нету" — only the general shape [[raw/Meeting_Transcript_NOVA_Remote_Game_Update_Architecture-October-30-2026.md]].

- **Three kinds of market (Pavel).** Strict locations with no updates and no internet; a middle kind where JVL decommissions, updates, and the lab ("интролот" — [[wiki/organizations/intralot.md|Intralot]]) knows the new checksums and confirms the software is certified; and markets with no outside control. Val: even with no outside control, "свой контроль на том же уровне, всё равно мы должны иметь" [[raw/Meeting_Transcript_NOVA_Remote_Game_Update_Architecture-October-30-2026.md]].
- **Server check and fingerprint (Pavel).** A cloud server holds every released version with its signatures. The machine downloads, computes checksums, sends a "fingerprint" of everything installed, and switches to the new software only if the server accepts it [[raw/Meeting_Transcript_NOVA_Remote_Game_Update_Architecture-October-30-2026.md]]. The server keeps a registry of all components with their checksums [[raw/Meeting_Transcript_NOVA_Remote_Game_Update_Architecture-October-30-2026.md]].
- **Two slots (Pavel).** As on Transactional, the master partition is duplicated; the update goes into the spare slot and the machine switches and reboots — "Это то, что называется раук". After 3 or 4 failed boots it switches back and comes up with the old set. At install slot A is written and slot B left empty; on update A is copied to B and the changed files written over it [[raw/Meeting_Transcript_NOVA_Remote_Game_Update_Architecture-October-30-2026.md]].
- **Modules (Pavel).** The second partition holds games, maths containers, bonuses as separate packages, the LGS and the progressive controller; each can be replaced alone if the server accepts the new set [[raw/Meeting_Transcript_NOVA_Remote_Game_Update_Architecture-October-30-2026.md]]. Almost all of the HAL moves into such packages; sound and LEDs are used by both the LGS and the game; the progressive controller, when master, is used by other machines on the network [[raw/Meeting_Transcript_NOVA_Remote_Game_Update_Architecture-October-30-2026.md]]. Files on that partition are signed one by one, not the whole partition; the fingerprint of it can go to GLI or Intralot, and CI/CD can compute the new checksums in advance [[raw/Meeting_Transcript_NOVA_Remote_Game_Update_Architecture-October-30-2026.md]].
- **A new paradigm (Chudinov).** Today games are "приколоченные гвоздями" to the software; the target is a container to which maths, games and settings can be added [[raw/Meeting_Transcript_NOVA_Remote_Game_Update_Architecture-October-30-2026.md]].
- **The compatibility map.** Chudinov: the hard part is which component may go on top of which — e.g. a game onto a given LGS, framework and progressive-controller version — "это прям карта получается целая". Pavel: start from "nothing may change" and allow small steps (6 games for 6 new ones; then 3 more on the same product). Chudinov: proven by test runs on a stand; Biratka: set automatically when a test passes; the result is a manifest the server uses [[raw/Meeting_Transcript_NOVA_Remote_Game_Update_Architecture-October-30-2026.md]]. Pavel: "искусственный интеллект" should track component compatibility [[raw/Meeting_Transcript_NOVA_Remote_Game_Update_Architecture-October-30-2026.md]].
- **Components first (Chudinov).** Split today's build into components with versions and a description; stored somewhere such as S3 (heard "вест 3 хранилище"; the notes: S3) — "сейчас Андрея нет" [[raw/Meeting_Transcript_NOVA_Remote_Game_Update_Architecture-October-30-2026.md]] [[raw/Meeting_Notes_NOVA_Remote_Game_Update_Architecture-October-30-2026.md]]. He wants a tool to compare two builds and list the differing components. Phase 0.5 = the split; phase 1 = assemble from components, check everything comes up, and keep a final document in GitHub of which combinations work [[raw/Meeting_Transcript_NOVA_Remote_Game_Update_Architecture-October-30-2026.md]]. Pavel: Chudinov already built the path from a GitHub release onward for the whole software; the same is needed per component. Chudinov: "относительно просто", a couple of days [[raw/Meeting_Transcript_NOVA_Remote_Game_Update_Architecture-October-30-2026.md]].
- **Patch or full image.** Pavel: where checksums are checked, skip patches and send the whole new system — "гигабайт", but certain [[raw/Meeting_Transcript_NOVA_Remote_Game_Update_Architecture-October-30-2026.md]]. Biratka: a patch could be made to give the same checksums as a full install — "2 килобайта или 2 гигабайта. Это большая разница"; worth testing. Chudinov: on Flex IQ, measured with Andrei, 300 MB took 20 to 30 minutes at about 6 Mbit/s; a gigabyte would be hours. Pavel: the operating system will change rarely; most changes go into small modules on the master partition [[raw/Meeting_Transcript_NOVA_Remote_Game_Update_Architecture-October-30-2026.md]] [[raw/Meeting_Notes_NOVA_Remote_Game_Update_Architecture-October-30-2026.md]].
- **Maths.** Biratka: maths is one Docker image, so a new game means a new maths image; why not maths per game? Pavel: the shared image is certified once at GLI and reused; a smaller game set can reuse it without a new pass. Chudinov: if the contract between game and maths stays the same, maths can be re-released alone; Pavel: yes, if the lab tests a build with new maths and old games, only the maths need go to remote machines [[raw/Meeting_Transcript_NOVA_Remote_Game_Update_Architecture-October-30-2026.md]]. Pavel also floated putting the LGS in Docker, so one artefact runs on x86 (FP7) and ARM [[raw/Meeting_Transcript_NOVA_Remote_Game_Update_Architecture-October-30-2026.md]].
- **LGS storage and statistics (Biratka).** Adding a game without losing history, or removing one, "сейчас просто нереализовано"; counters and daily statistics of a removed game must go [[raw/Meeting_Transcript_NOVA_Remote_Game_Update_Architecture-October-30-2026.md]]. Chudinov: the machine gets a new game list; old statistics need not be deleted but must not show. Pavel: reserve space for future games, or dump the storage and regenerate it after a game change; Biratka: "возможный вариант". Biratka: keep the last records in fast storage and move them to the database when idle — writing to two places at once can split a transaction [[raw/Meeting_Transcript_NOVA_Remote_Game_Update_Architecture-October-30-2026.md]].
- **x86 and ARM storage.** Pavel: x86 has fast NVMe; ARM has slower, likely less reliable eMMC; the board has an SD slot, so the database could sit on a replaceable card. Biratka and Chudinov want one approach on both [[raw/Meeting_Transcript_NOVA_Remote_Game_Update_Architecture-October-30-2026.md]].
- **Who runs the update on the machine.** Biratka: not decided — LGS or another application. Chudinov: on Flex IQ a RAUC application starts first, talks to the server, checks checksums, applies and rolls back; the LGS is unlikely to update itself [[raw/Meeting_Transcript_NOVA_Remote_Game_Update_Architecture-October-30-2026.md]].
- **After the update.** Biratka: a self-check — checksums, boot, picture — and perhaps watching the machine for days [[raw/Meeting_Transcript_NOVA_Remote_Game_Update_Architecture-October-30-2026.md]]. Pavel: fake spins on all games at start-up, kept out of statistics. Chudinov: on the IQ terminal a health check passed while the browser hung; about 90% of what a person checks can be tested [[raw/Meeting_Transcript_NOVA_Remote_Game_Update_Architecture-October-30-2026.md]]. Val: if no money enters the machine for about a day after an update, that is a problem (heard "20 04:00"; the notes: about 24 hours) [[raw/Meeting_Transcript_NOVA_Remote_Game_Update_Architecture-October-30-2026.md]] [[raw/Meeting_Notes_NOVA_Remote_Game_Update_Architecture-October-30-2026.md]]. Biratka: if nothing was played, roll back and/or alert; Pavel: once games are played, going back is not possible [[raw/Meeting_Transcript_NOVA_Remote_Game_Update_Architecture-October-30-2026.md]]. The old version stays in the second slot; what the LGS keeps in storage must be restored too (Pavel) [[raw/Meeting_Transcript_NOVA_Remote_Game_Update_Architecture-October-30-2026.md]].
- **The progressive master.** If the machine holds the progressive master, update one machine first, move the master with its current levels there, then update the rest (Pavel) [[raw/Meeting_Transcript_NOVA_Remote_Game_Update_Architecture-October-30-2026.md]].
- **Copy proven practice (Val).** Adopt how companies such as Apple update devices, "чтоб мы не все выдумывали сам", and always split releases into MVPs [[raw/Meeting_Transcript_NOVA_Remote_Game_Update_Architecture-October-30-2026.md]].
