# The hardware agent's instructions move to the persona repository, and any AI model can do the work from GitHub (Oct 29 2026)

Decided by [[wiki/people/val-levitan.md|Val Levitan]] with [[wiki/people/nathan-carver.md|Nathan Carver]] and [[wiki/people/genadi-peari.md|Genadi Peari]] at the [[wiki/meetings/2026-10-29-hardware-parts-first-generated-data-contract-and-persona-repo.md|Oct 29 2026 call]], 2:02–2:28 PM Eastern, in English. Quotations are from the transcript [[raw/Meeting_Transcript_Hardware_Parts_Data_Contract_Generation_and_Persona_Repo-October-29-2026.md]] unless marked.

## How contract generation works (Nathan)

- **Source files.** Whatever the vendor gives — Val: "data sheets, technical drawings, specifications, connector diagrams, PIN diagrams, whatever it is, we collect it, we put it into Github." Nathan: "we're still honestly still settling on terminology".
- **Two human steps for a new part.** "Add all of your… source files to the folder. Create the item YAML file." The YAML is "the item card, like the high level data for the item card in Msbc". "And then we can run the agent to generate the contract file." The contract is used "Further downstream, build the BOM using this as a component within it."
- **The example part.** Val first read the item as a cabinet ("That's an assembly"); it is a main door for Flex Pay that Genadi designed — "it came out from SolidWorks… You designed it." Nathan: "In this instance… Jvl is the vendor". Genadi: "Same logics."
- **The repository instructs the agent.** "This repository is self-instructing on how to read it, on how to find the information." Agents can also add the source files and write the item YAML, since they have the folder instructions; the human step is checking "is all of this looking correct?" before the contract is generated. "once our source is structured and consistent within that structure, generating contracts will be consistent."
- **Three days on the structure.** Genadi: "We spent actually three days for generating the right structure because it was an inconsistency every time"; they reached full understanding "just yesterday". Nathan: not every root component folder "is going to fall into the same structural pattern"; they iterate on a pattern per group of components. The contract is "better than… The previous spike that I… had done, now that… Genadi has his… structure in place".

The notes record the same flow [[raw/Meeting_Notes_Hardware_Parts_Data_Contract_Generation_and_Persona_Repo-October-29-2026.md]].

## Learning and checking

- **Val's picture.** "an agent, in effect, is a persona." It gets a source of truth and a personality — "You act like this… That's what you look at" — and uses the knowledge base and the logic for "Creating a bill of material." To learn from mistakes "we need to have an auditor of some sort… another agent who… looks at the truth and says… You made a mistake."
- **Nathan.** "There has to be verification of the output… we can use another agent to verify the work", plus human review when people meet the final output. "the way that our learning would be refining the instructions and the scripts that do the work."

## What was decided

- **The agent's instructions move to the persona repository.** Val: "We have repository for personas." Nathan did not know: "Oh, okay. I didn't know that." Val: "if you get together with Andrei Bosik… he'll… tell you what it is. For example, he is working on AI Project Manager"; "we have a CO… We have a Cfo" (the notes: AI-COO, AI-CFO); "all of the persona lives in a persona files repository." Nathan expects some instructions to stay in the hardware repository and some to move; Val: "Yes, it needs to move to a persona, Req." [[raw/Meeting_Transcript_Hardware_Parts_Data_Contract_Generation_and_Persona_Repo-October-29-2026.md]] [[raw/Meeting_Notes_Hardware_Parts_Data_Contract_Generation_and_Persona_Repo-October-29-2026.md]]
- **GitHub is the source of truth for any agent.** Nathan asked whether people use the agent on their local machines or a cloud tool. Val: "we use Claude Code… although it lives locally, the reference, the source of truth is the Github." "we could use Grok or we could use any cloud services pointed to the same Github repository and ask an outside agent to do exactly the same work as the local… Claude code would do… I don't see why we need to be married to… a single… Ai model." Nathan: "No, no, we're not."
- **Vendor admin data stays out of GitHub.** The technical data goes from GitHub into MSBC, "But… It needs a second push for the same vendor… Of all the administrational data… which is not a Github related. We don't want it in Github." Today it lives only in MSBC ("I don't know whether we should change it or not"), reachable by "the administrational way of the company, not by engineering… And… not by procurement people." "we want to have a division… Of… power."
- **Missing data stops the BOM.** Val's example: to replace a monitor in a sub-assembly, send an RFQ to monitor suppliers and have the agent "yank… the dimensions… out of the Github and include it" with the data sheets. Genadi: descriptions must grow — dimension, brightness, interface, LED backlight. Val: all of it must be in the data sheet put into GitHub "Before the data contract"; screws the same (thread, depth, radius). "if we don't have this information, we should not be able to form a complete bomb. It should collapse. That's our checkpoint."
- **Next review Wednesday, Nov 4, 2:00 PM Eastern, 30 minutes.** Val first asked for Monday afternoon; after Genadi described his remaining work: "let's do it on Wednesday… I'll set up a meeting for 2 P.m. Eastern Time on Wednesday. I'll book it for half an hour." The notes date it Nov 4 2026 [[raw/Meeting_Notes_Hardware_Parts_Data_Contract_Generation_and_Persona_Repo-October-29-2026.md]].

And then the final step… syncing this information with Msbc." His next milestone: "reach out to Andrei and hook into the persona repo… refine the instructions, generate consistent contracts."

Genadi asked Nathan to help pull them "carefully category by category"; Nathan: "Yeah, I can help with that."
- **The AI COO.** Val: "I want to point the CO persona… to the same repository. I have a I CO… whose responsibility is to look after purchasing and manufacturing." He asked for the repository link; Nathan: "Yes." (The notes: Nathan sent it during the call.) In one line: **a part's source files and item YAML go into GitHub, the agent writes the contract and later the BOM, the agent's persona lives in the persona repository, any AI model can do the work from the same GitHub, admin vendor data stays in MSBC, and a BOM with missing data must fail.**

## How it sits against earlier rulings

- **One repository, the contracts from data sheets.** The work happens inside the one hardware repository ruled on Oct 21 — [[wiki/decisions/2026-10-21-hardware-parts-go-into-one-repository-with-subfolders-and-the-first-spike-builds-the-power-supply-bom-automatically.md]] (Oct-29 update) — and applies the Oct-19 rule that the agent writes the contracts from vetted data sheets — [[wiki/decisions/2026-10-19-hardware-repositories-start-with-harness-display-and-sheet-metal-and-the-agent-generates-data-contracts-from-vetted-data-sheets.md]].
- **The control gate.** "It should collapse" restates the Oct-13 rule that the agent's BOM is the test of the data — [[wiki/decisions/2026-10-13-the-agent-builds-the-bom-as-a-control-gate-taught-by-data-contracts-not-cad-and-genadi-finds-why-it-is-wrong.md]] (Oct-29 note).
- **The border.** Admin data kept out of GitHub fits "administration never changes GitHub" — [[wiki/decisions/2026-09-30-engineers-never-change-msbc-and-administration-never-changes-github.md]] (Oct-29 note).
- **Agents and one knowledge source.** Earlier the same day the company second brain became the one knowledge source for all agents — [[wiki/decisions/2026-10-29-the-company-second-brain-is-the-one-knowledge-source-for-all-ai-agents-with-access-limited-per-agent-and-the-game-design-agent-sees-game-knowledge-only.md]]. How the persona repository and the second brain fit together was not discussed here (link is context only).
