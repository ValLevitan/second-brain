- **Chudinov's alarm.** He asked whether everyone is comfortable with the current requirements: in "Полгодика это будет какая то страшная мусорка, непонятная кто какие и откуда дублируются, редактируется"; "почти нереально это всё смотреть и сводить в конце с концами". The main problem: "они не систематизированы, они размазаны какимто вот тонким слоем о всём подряд. Я не знаю, сколько их я не знаю сколько дублей." - **The count.** Kovalchuk: "У нас сейчас порядка 1100 реклариментов… какое количество из них дублируют, дублируется, никто не знает" [[raw/Meeting_Transcript_Daily_Standup_Requirements_Sprawl_and_Claude_Review_Merge_Gate-November-24-2026.md]]. (See Open contradictions below for Irina's Nov-21 figure.)
- **His example of a conflict.** One capability says the port must block when the location is blocked; another says that with no network "спортс с машиной работает" — so a blocked location with the port cut off from the network gives "2 взаимоисключающих" [[raw/Meeting_Transcript_Daily_Standup_Requirements_Sprawl_and_Claude_Review_Merge_Gate-November-24-2026.md]]. Pavel: one must take priority — "надо носить изменения и править" [[raw/Meeting_Transcript_Daily_Standup_Requirements_Sprawl_and_Claude_Review_Merge_Gate-November-24-2026.md]].
- **His idea: a product spec in GitHub.** Start "от спеки на продукт, который, например, будет в гетхабе лежать" — for example the Flex IQ Port, with sections for communication with the machine, with the ITO and with the cloud — approved by pull requests, then linked into Jira; GitHub holds the description and Jira the management and acceptance criteria. What he wants is a record with change history — what was accepted when, what was dropped, struck through — "по сути, база знаний", so the current state can always be read [[raw/Meeting_Transcript_Daily_Standup_Requirements_Sprawl_and_Claude_Review_Merge_Gate-November-24-2026.md]] [[raw/Meeting_Notes_Daily_Standup_Requirements_Sprawl_and_Claude_Review_Merge_Gate-November-24-2026.md]].

Chudinov: "Не не, не согласен. Capelise это набор фич." Pavel also saw a missing layer "который описывает, с одной стороны, постановку задач, а с другой стороны релизное состояние"; an MVP in Jira today is only "223 предложения" (two or three sentences) and then the capability links. She had raised the same problem "в пятницу или в субботу" (Pavel) [[raw/Meeting_Transcript_Daily_Standup_Requirements_Sprawl_and_Claude_Review_Merge_Gate-November-24-2026.md]].

## 2. The Claude-review merge gate

- **Bosik's new standard.** If he has time today he will publish a GitHub standard "который будет запрещать merch в случае, если… клод ревью оставила" a red mark: "если клод ревью оставляет красный кружочек, надо его… Исправлять", re-run the review by hand, and when it no longer leaves red marks "Merch пройдёт". He has been testing it on a test repository for two days [[raw/Meeting_Transcript_Daily_Standup_Requirements_Sprawl_and_Claude_Review_Merge_Gate-November-24-2026.md]].
- **Pavel's exception.** If someone decides a red item need not be fixed in this pull request and replies, for example, that it will be done in another one — "Почему не разрешать кормить в таком случае?" ("кормить" = merge) — block only "если красный есть и нету ответа на этот красный" [[raw/Meeting_Transcript_Daily_Standup_Requirements_Sprawl_and_Claude_Review_Merge_Gate-November-24-2026.md]].
- **The ruling.** Bosik: on GitHub "Нельзя там очень много чего автоматизировать" for this; "в целом политика такая, что… с красным кружком меж проходить не должен. Исключительно ситуации будут. Я это продумал там, но я ещё не все сценарии протестировал." Pavel: "Хорошо." [[raw/Meeting_Transcript_Daily_Standup_Requirements_Sprawl_and_Claude_Review_Merge_Gate-November-24-2026.md]] The notes: exceptions will be defined in the standard [[raw/Meeting_Notes_Daily_Standup_Requirements_Sprawl_and_Claude_Review_Merge_Gate-November-24-2026.md]].
