# The RIS improvements release notes are settled point by point (Oct 20 2026)

Settled at the [[wiki/meetings/2026-10-20-ris-improvements-release-notes-review.md|Oct 20 2026, 10:49 AM release-notes review]] by [[wiki/people/val-levitan.md|Val Levitan]] with [[wiki/people/felipe-miranda.md|Felipe Miranda Giorgi]], [[wiki/people/pavel.md|Pavel Frolov]] and [[wiki/people/irina-shishko.md|Irina Shishko]]. Val read the release notes aloud, one point at a time, and fixed the wording. Point 1 had been reviewed earlier without a recording; Val repeated the changes on the record [[raw/Meeting_Transcript_RIS_Improvements_Release_Notes_Review-October-20-2026.md]]. The same day, at 1:11 PM, the printed notes were shown to a customer — see [[wiki/decisions/2026-10-20-diamond-gets-the-ris-improvements-first-on-p1-p2-and-p3-at-the-end-of-november-and-the-two-machine-trial-is-extended.md]].

*(Mostly English. Some parts are Russian or garbled speech-to-text; the notes name the garbled stretches [[raw/Meeting_Notes_RIS_Improvements_Release_Notes_Review-October-20-2026.md]]. Nothing is recorded from them except where a speaker's point is clear.)*

## Point by point

1. **Battery.** Remove the word "new" in "new setup file on the USB". Remove "A lost date and time is no longer a critical error", the question "will the clock need to be set up again", and the statement "I do not know yet" [[raw/Meeting_Transcript_RIS_Improvements_Release_Notes_Review-October-20-2026.md]]. Val also read a battery sentence ("Even after the battery has died, completely stays, but..." — garbled; what changes in it is **unclear**). At 1:11 PM the first item shown to the customer was the battery: no hard reset after a battery change [[raw/Meeting_Transcript_Diamond_Amusement_RIS_Improvements_Release_Preview-October-20-2026.md]].
2. **Software upgrade — Val's rewrite, agreed.** "Today, every upgrade needs a new setup file from Jvl on USB for each machine. After the release, the machine keeps its full configuration through an upgrade." The configuration means cabinet, peripherals, games, bet buttons and denominations (Pavel: "Yes"). "If the game map [math] does not change, a new setup file is not required. In the event a new setup is required, the machine would have to get a new download through a modem or a USB." Val: "Okay, agreed." Along the way Pavel noted that "It could be 1 USB stick containing set of RIS files related to each particular machine", and that a new USB setup file is exported from the CMS. Irina (Russian): if the games or main settings change — bet buttons, game percentages — a new RIS from a USB stick is needed; if not, the old RIS can be used [[raw/Meeting_Transcript_RIS_Improvements_Release_Notes_Review-October-20-2026.md]].
3. **Printer on/off.** The soft-reset question is removed ("We can remove this question" — Pavel; Val: "I'm removing it completely"). The statement stays: "there is no hard reset, no new setup files, no USB, and no call to Jvl" — Pavel: "Yes, correct." Felipe asked whether the printer on/off switch is available "at any point during the machine's life cycle before a hard reset"; Pavel: "Yes… Even if money was still placed on the machine." Felipe's other worry — a printer with the wrong firmware that the machine does not recognise — he called "not relevant to on-off on a Tito printer" [[raw/Meeting_Transcript_RIS_Improvements_Release_Notes_Review-October-20-2026.md]].
4. **Lease when JVL's records do not match the machine.** Today the machine waits until someone at JVL fixes the records. After the release the lease is issued on its own, for the software the machine actually has, "with no action at Jvl and no passport step." Pavel: someone still has to scan the updated lease, but "It can be any personal without any login access." The lease runs for "The period the same as the previous installation"; "It will not expand existing Lease." Felipe: many fully paid machines work until 2030; Pavel: "it will work until… End of life." Val added one sentence: "**the current lease period will remain unaltered**"; Pavel: "Exactly." [[raw/Meeting_Transcript_RIS_Improvements_Release_Notes_Review-October-20-2026.md]]
5. **Replacing a peripheral.** Val: instead of "part", "a peripheral. Such as a bill acceptor"; instead of "today", "currently" — "For every such case." Currently, at the next reset, the machine stops at the passport screen and a technician must photograph a QR code, send it to JVL, wait for a code and enter it. After the release the machine registers the new peripheral on its own and goes back to play. Pavel: "for final user, it will looks like yes. But actually under the hood, it will postpone update of passport until next Lease scan"; Felipe: the lease scan "will not be user login sensitive". Val: "it doesn't really matter for the sake of this." [[raw/Meeting_Transcript_RIS_Improvements_Release_Notes_Review-October-20-2026.md]]
6. **Machines missed during an upgrade — Felipe's paragraph.** See the next section.
7. **Critical errors.** Pavel: "I'm not sure that we can cover all the possible issues right now", and "I'm not sure that to be actually implementing new list of error codes." The yellow screen "will be changed to specify some particular messages related to this error"; the QR code will carry "the error code, serial number and software version." Felipe's idea: the QR code opens a page with "the most probable causes" and "troubleshooting steps". Pavel: "In the future, I think on the server side, we will be able to implement some logic, including AI." Val's wording: "after the release the screen. Will name the… cause of the error." Pavel: "Yes." [[raw/Meeting_Transcript_RIS_Improvements_Release_Notes_Review-October-20-2026.md]]
8. **Lease renewal.** "That's very clear" (Felipe). No change [[raw/Meeting_Transcript_RIS_Improvements_Release_Notes_Review-October-20-2026.md]].
9. **The last paragraph (transaction history).** Pavel proposed a filter at the top of the existing transaction screen — for example, cash-outs only. Felipe: "that doesn't resolve the problem that we have very limited… entries. So in two hours of play, the information that I need from the cash out two hours ago could be deleted" (today "81 pages of about 20 records"). Pavel: "let's left in this written form." [[raw/Meeting_Transcript_RIS_Improvements_Release_Notes_Review-October-20-2026.md]]

## Point 6 — the missed machine

- **Felipe's case.** JVL prepares an upgrade for, say, 20 cabinets: 20 RIS sticks and a few software sticks. The customer upgrades 18 and forgets 2. Today, when the lease expires and they re-scan, the machine shows a settings mismatch; "Your boss probably lost the setup files for those two. You need to come to Jvl, pick it up, go back and install the new RIS." He had such a call "yesterday" [[raw/Meeting_Transcript_RIS_Improvements_Release_Notes_Review-October-20-2026.md]].
- **After the release** the missed machine keeps working on its old RIS "until lease date specified during installation" (Pavel). Felipe: then a machine leased to the 2030s is not upgraded until 2030. Pavel: "in the Cms, I assume that we will have additional reporting for those machines that are used… previous RIS files while the new one is available." [[raw/Meeting_Transcript_RIS_Improvements_Release_Notes_Review-October-20-2026.md]]
- **Pavel's three options** for the next lease scan when a newer RIS exists: refuse the lease ("You need to reinstall software"); keep issuing it until the old lease end; or keep issuing it until the new RIS's lease date ("For example, one year") [[raw/Meeting_Transcript_RIS_Improvements_Release_Notes_Review-October-20-2026.md]].
- **Felipe's proposal:** a warning that a software upgrade is required, with a time limit — "a month, you must upgrade to new software by such and such" date. Pavel: "we can allow, for example, one, one more interval… Lease update interval… And saying that, after this, we will avoid… this generation for this software and you must update it to newer software." Felipe: "I think that's the best course of action." [[raw/Meeting_Transcript_RIS_Improvements_Release_Notes_Review-October-20-2026.md]]
- **Val did not rule on the behaviour.** "I totally tuned off… So if you tell me how to switch the wording, I'm OK, whichever way. My goal is to make sure that our customers in Georgia are satisfied." Later he put Felipe's written paragraph in as point 6: "Okay, so now we have our number six." [[raw/Meeting_Transcript_RIS_Improvements_Release_Notes_Review-October-20-2026.md]] At the customer that afternoon Felipe read it as: "machine receives temporary lease renewal and displays upgrade pending" [[raw/Meeting_Transcript_Diamond_Amusement_RIS_Improvements_Release_Preview-October-20-2026.md]].
- **No "bank" on the street (Val).** When Pavel framed the case as some machines of a bank not getting the new RIS, Val: "for Georgia or for any street location, the concept of a bank should not be valid… a bank has only relevance in a casino setup… for street operation, there is no bank… each machine is individual." Pavel explained the original case as one progressive controller tied to a group of machines, with three of four upgraded [[raw/Meeting_Transcript_RIS_Improvements_Release_Notes_Review-October-20-2026.md]].
- **Irina's case (Russian, partly garbled).** The newest software has 15 games, and only 8 can be on the machine at a time. A RIS with 8 games is installed; later someone makes a new installation with 8 different games on the same software. Which RIS may then be applied, and what lease is issued? ("Какой рис? Применять в таком случае разрешаться… Какую лизу выдаваться?") Irina's own leaning: if the games changed, the new set-up must be taken ("Учились игры, меняем, значит всё" — Pavel: "Да"). No clear answer is on the record [[raw/Meeting_Transcript_RIS_Improvements_Release_Notes_Review-October-20-2026.md]].
