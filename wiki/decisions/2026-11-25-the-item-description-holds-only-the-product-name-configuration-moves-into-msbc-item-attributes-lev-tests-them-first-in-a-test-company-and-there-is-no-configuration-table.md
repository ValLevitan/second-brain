# The item description holds only the product name; configuration goes into MSBC item attributes; Lev tests first; no configuration table (Nov 25 2026)

Taken at the [[wiki/meetings/2026-11-25-msbc-item-attributes-vs-description-and-part-revisions.md|Nov 25 2026, 12:31 PM meeting "MSBC - Description and Attributes"]] (Russian, a few lines in English) between [[wiki/people/val-levitan.md|Val Levitan]], [[wiki/people/lev-rudky.md|Lev Rudky]] and [[wiki/people/genadi-peari.md|Genadi Peari]] [[raw/Meeting_Transcript_MSBC_Item_Attributes_vs_Description_and_Part_Revisions-November-25-2026.md]] [[raw/Meeting_Notes_MSBC_Item_Attributes_vs_Description_and_Part_Revisions-November-25-2026.md]]. MSBC = Microsoft Business Central; the system side is on [[wiki/topics/business-central-erp-implementation.md]].

## 1. What Val wants — description apart, attributes apart

- **The problem.** When JVL creates a part number it should stop the "гимнастикой. Интерпретации. Айтэма в доскрепше", because "это тяжело клиенту объяснить, что какое это на инвойсе" and it "Негативно отражается на, как мы это продаём" [[raw/Meeting_Transcript_MSBC_Item_Attributes_vs_Description_and_Part_Revisions-November-25-2026.md]].
- **What MSBC offers.** Val read that Business Central separates the description from product attributes, "то, что очень удобно, особенно в нашем положении"; JVL never used attributes before ("Мы никогда это не знали и никогда в этом не думали") [[raw/Meeting_Transcript_MSBC_Item_Attributes_vs_Description_and_Part_Revisions-November-25-2026.md]]. The notes add that an attribute can be text, a number, a date and so on [[raw/Meeting_Notes_MSBC_Item_Attributes_vs_Description_and_Part_Revisions-November-25-2026.md]].
- **The example.** The description should say only the product — on tape "Вот флэг айкьюк a shire torm minal", which the notes read as "Flex IQ Share Terminal" — "А все остальное было частью атрибютов". IQ 1 and IQ 2 would be two bills of material; for IQ 1 the attributes are things like a single screen, the base colour, a scanner and no magnetic card reader. Val: "IQ 2 это с модомом и с 2 телевизорами. И с. Кальдрейдером" (modem, two screens, card reader) [[raw/Meeting_Transcript_MSBC_Item_Attributes_vs_Description_and_Part_Revisions-November-25-2026.md]] [[raw/Meeting_Notes_MSBC_Item_Attributes_vs_Description_and_Part_Revisions-November-25-2026.md]].
- **Why it fits JVL.** All items are a flat collection in GitHub, each with its data sheet; the data sheets already hold the attributes, so the agent that forms the items can open them in MSBC and fill the attributes, "потому что атрибют и это часть дельта контракта" (data contract) [[raw/Meeting_Transcript_MSBC_Item_Attributes_vs_Description_and_Part_Revisions-November-25-2026.md]]. Background: [[wiki/decisions/2026-11-23-genadi-first-finishes-the-data-contracts-and-loads-every-data-sheet-into-github-and-supplier-search-becomes-agent-logic-built-on-them.md]].
- **Val's questions.** Are attributes already enabled in MSBC; if not, what does it take; if yes, can JVL experiment with moving data from the data contracts into the item description and item attributes, using standard agents [[raw/Meeting_Transcript_MSBC_Item_Attributes_vs_Description_and_Part_Revisions-November-25-2026.md]].
- **Genadi agreed on attributes.** "атрибьют это очень это необходимо просто для всех парк намберска эти 1000 номеров". Val: not only handy but needed, because all JVL knowledge is based on data sheets and data contracts, "И когда мы делаем прочие соли заказ, мы должны повторять эти атрибюты" [[raw/Meeting_Transcript_MSBC_Item_Attributes_vs_Description_and_Part_Revisions-November-25-2026.md]].

## 2. Lev — test first in a test company

- Lev could not answer "за 2 минуты" — "Ответ на это наверное да" — but wants to "взять, какоето простое изделие. И поэкспериментировать с ним" [[raw/Meeting_Transcript_MSBC_Item_Attributes_vs_Description_and_Part_Revisions-November-25-2026.md]].
- Does anything need to be enabled? Lev: "Скорее всего, еще нет", but a small system must be run through to check that attributes cause no problems "с другими документами, там с перчасами, ордерами, с инвойсами"; "Я думаю, что всё будет работать, но нужен верификаш". Genadi: "Атрибеты должны появиться на пиоус" (on the POs). Lev does it himself for now, not through a consultant ("Пока сам") [[raw/Meeting_Transcript_MSBC_Item_Attributes_vs_Description_and_Part_Revisions-November-25-2026.md]].
- **The test item.** Val: "Давайте работать пару суем" (the power supply), since he works with Nathan on it too. It is an old assembly, not a new one; Genadi found it has one level and offered to add more; Lev: "Может сделать 3". The test runs "В тестовой системе", in a fresh copy of the company, not the live one. Val: "через день 2 мы будем знать про атрибуты" [[raw/Meeting_Transcript_MSBC_Item_Attributes_vs_Description_and_Part_Revisions-November-25-2026.md]].
- **Default attributes are not enough.** Genadi sees attribute fields in MSBC, but the defaults are few — material, colour and the like; JVL needs its own, "бил валидатора ти принтера. Какие там дополнительные девайсы" [[raw/Meeting_Transcript_MSBC_Item_Attributes_vs_Description_and_Part_Revisions-November-25-2026.md]]. Lev: whoever orders a part number must not be able to forget an attribute or a customer's specific need [[raw/Meeting_Transcript_MSBC_Item_Attributes_vs_Description_and_Part_Revisions-November-25-2026.md]].

## 3. Part revision — asked by Genadi, not decided

- **The need.** MSBC has no revision today, "и это действительно болит"; Genadi types the revision into the description by hand, "как раз то, что вал не хочет". He asked whether revision can be an attribute or a separate field [[raw/Meeting_Transcript_MSBC_Item_Attributes_vs_Description_and_Part_Revisions-November-25-2026.md]].
- **What a revision is.** The lowest level, a part. His example: a monitor bracket that must now also take new controllers gets "ревизию b" instead of A — same function, more holes or fasteners, backward compatible. If it is not backward compatible, "нужно менять номер" [[raw/Meeting_Transcript_MSBC_Item_Attributes_vs_Description_and_Part_Revisions-November-25-2026.md]].
- **Val.** "Я видел, что ревизии нету", but perhaps a change of one part number in a sub-assembly can change the sub-assembly's revision; "Я должен подумать чутьчуть" [[raw/Meeting_Transcript_MSBC_Item_Attributes_vs_Description_and_Part_Revisions-November-25-2026.md]].
- **Lev's own concern.** The bill of material must always carry the latest board revision, and he needs a cut-over process — for example "собирают 20 машин, а у тебя 7 бортов старых, остальные все новые"; "это отдельная тема". Genadi has no instructions for this: he cannot simply swap the board in the BOM, because the old one would stop being consumed ("он перестанет списываться") [[raw/Meeting_Transcript_MSBC_Item_Attributes_vs_Description_and_Part_Revisions-November-25-2026.md]].

## 4. No configuration table — the requirements are the source of truth

- **Genadi's table.** He keeps a table in GitHub of the final Flex product numbers that Claude can read; JVL sells "8 наименований флекса" (IQ has one model so far), each market with its own needs — for example a South Dakota cable for the Light & Wonder controller [[raw/Meeting_Transcript_MSBC_Item_Attributes_vs_Description_and_Part_Revisions-November-25-2026.md]] [[raw/Meeting_Notes_MSBC_Item_Attributes_vs_Description_and_Part_Revisions-November-25-2026.md]]. He asked how [[wiki/people/felipe-miranda.md|Felipe]] (sales) and [[wiki/people/elizabeth.md|Elizabeth]] (production) will pick the right number without it.
- **Val's answer.** They ask Claude which part number matches the configuration they need; this is a standard function, "Это даже кастомизировать не надо". "Нам нам не нужна, нам не нужна Таблица, и я против таблиц"; "Если есть какаято Таблица, я бы её уничтожил", because everything must be built on the data contract and a table has to be maintained, which is very hard "особенно при минимальном став" [[raw/Meeting_Transcript_MSBC_Item_Attributes_vs_Description_and_Part_Revisions-November-25-2026.md]].
- **Why.** The table lives in one person's memory: "Как только вас нету, эта Таблица похоронена." The only source of truth is the requirements — legislative, non-functional and functional. The legislation for South Dakota, Nebraska, Georgia and Texas is already in GitHub ("полный числешен на салта на небраска на jurgia и на тэксис"; "салта" = South Dakota, §4 garble). If the requirement to connect to the controller is missing, "вы не можете правильно сделать акцептон скратерия. Вы не можете правильно сделать тест" [[raw/Meeting_Transcript_MSBC_Item_Attributes_vs_Description_and_Part_Revisions-November-25-2026.md]].
- **Today it works on people.** Val: it works now because Genadi, Lev and [[wiki/people/irina-shishko.md|Irina Shishko]] support each other — Irina remembers the cable, Genadi has the table, Lev knows how the business works — "Ну это неправильно" [[raw/Meeting_Transcript_MSBC_Item_Attributes_vs_Description_and_Part_Revisions-November-25-2026.md]].
- **Genadi not convinced.** He wants to rule out human error — a configuration that does not exist, or the wrong bill validator; "Это не это не хороший пронт" for a salesman who must remember each customer's parts. Val: the customer names the exact product, and "Я думаю, что это довольно тревел вещь" (trivial). After Val's part, Genadi told Lev he did not understand what Val wants [[raw/Meeting_Transcript_MSBC_Item_Attributes_vs_Description_and_Part_Revisions-November-25-2026.md]] [[raw/Meeting_Notes_MSBC_Item_Attributes_vs_Description_and_Part_Revisions-November-25-2026.md]].

## 5. Sub-assemblies without the manufacturing module; MCP gaps as use cases

- **No production orders in JVL's BC.** Lev: "Продакшн ордерс нет. Вообще, но у нас есть обходные пути"; Val: JVL's BC has no manufacturing module with sub-assemblies counted and shelved [[raw/Meeting_Transcript_MSBC_Item_Attributes_vs_Description_and_Part_Revisions-November-25-2026.md]]. Same set-up as the June-2025 choice on [[wiki/topics/business-central-erp-implementation.md]].
- **Val: not needed.** "Мы протестировали уже с Геннадием. И с нейтоном": from data sheets a sub-assembly (the power supply) can be built and kept in MSBC as its own part number with its own assembly; Flex could be built from such part numbers, "Но нам это тоже не нужно. Потому что мы можем сразу собирать довольно линейно все" [[raw/Meeting_Transcript_MSBC_Item_Attributes_vs_Description_and_Part_Revisions-November-25-2026.md]]. The test he means is read as the Nov-18 spike on [[wiki/decisions/2026-11-16-the-agents-build-the-bom-unguided-from-a-product-description-and-the-data-contracts-the-data-sheet-is-the-source-of-truth-and-nathan-spikes-a-simple-sub-assembly.md]] (**inference**).
- **Writing into MSBC.** Lev's Claude prepares data, but its ability to write is limited, "потому что это должно быть сделано на уровне нейтона". Val: MCP sits on top of the API; when a function is missing he asks Claude Code in the same session to write a use case for [[wiki/people/nathan-carver.md|Nathan]] and put it in GitHub, and can have a Jira task opened for [[wiki/people/dmitri-kovalchuk.md|Dima Kovalchuk]], who is adding missing functions to an MCP an engineer gave JVL; "Я могу вас научить, как это делается" [[raw/Meeting_Transcript_MSBC_Item_Attributes_vs_Description_and_Part_Revisions-November-25-2026.md]]. Same rule as Nov 20 on [[wiki/decisions/2026-11-20-genadi-works-only-on-the-bom-with-nathan-not-procurement-and-his-purchasing-know-how-goes-into-standards-checked-daily-by-his-own-po-agent.md]].
- **Val's view of the tool.** When Business Central was built there was no AI; Claude Code now has its own docs, slides, sheets and whiteboard, and the dependence on Microsoft applications is fading. Recorded as his opinion [[raw/Meeting_Transcript_MSBC_Item_Attributes_vs_Description_and_Part_Revisions-November-25-2026.md]].

## 6. Assembly shortages, the warning label, outside labour (Lev and Genadi)

- **Why Lev posts assemblies, not Elizabeth.** Posting an assembly hits shortages — about 40 recently, mostly small (tape, labels, packaging); he judges each one, adjusts and posts again. He suggested that Nathan load the needed data into the assembly order and check the drawings before Elizabeth posts; "то это всё на порядок упроститься" and she could do it [[raw/Meeting_Transcript_MSBC_Item_Attributes_vs_Description_and_Part_Revisions-November-25-2026.md]]. Lev added he does not remove items from the BOM; what he drops when assembling are fractions tied to old or future revisions [[raw/Meeting_Transcript_MSBC_Item_Attributes_vs_Description_and_Part_Revisions-November-25-2026.md]].
- **The AC warning label.** Genadi: a cheap label must be fixed on every power-supply plate where there is AC; "Из за этого могут люди в тюрьму сесть". He said "миша её не покупает", Elizabeth does not apply it, and Lev probably drops it; his only tool is the BOM, so when Val proposes removing cheap items, they will not come back. The notes call it a high-voltage label [[raw/Meeting_Transcript_MSBC_Item_Attributes_vs_Description_and_Part_Revisions-November-25-2026.md]] [[raw/Meeting_Notes_MSBC_Item_Attributes_vs_Description_and_Part_Revisions-November-25-2026.md]]. "миша" is read as [[wiki/people/mikhail-perelman.md|Mikhail Perelman]] by the §4 procurement context (**inference**). No owner was set.
- **Outside labour as a resource.** Lev: outside labour (for example coating) whose result does not come back to stock must be set up "не как айти. А как ресурс"; a purchase order for a resource "никак не влияет на инвенторий". The coating round trip (out, back, out again) has no answer yet, "но он будет" [[raw/Meeting_Transcript_MSBC_Item_Attributes_vs_Description_and_Part_Revisions-November-25-2026.md]].
