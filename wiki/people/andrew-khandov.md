## Feature-branch discipline (Val's rules, Feb 3)

Val's homework and standing rules for the Miranda work: baseline all V8 features on one big "V8" branch as the first commit, merge to main via pull request, then open feature branches for in-progress **V9** work. Best practices Val insists on: every feature branch tied to a Jira story/feature that is in the correct issue state; branches **not long-lived** (open no more than ~a week in the shared registry, though local branches can live longer); a feature branch tied to completed work but stuck in backlog/done-mismatch will get him "raked over the coals."
